# Harrow Studio

Windows desktop companion for the Redragon Harrow Pro G808.

## Stack and architecture

- **HarrowStudio.Domain** — profiles, button bindings, macros, and controller state.
- **HarrowStudio.Application** — use cases and contracts for profile storage and controller input.
- **HarrowStudio.Infrastructure** — local JSON profiles, XInput/DInput polling, and GitHub release updates.
- **HarrowStudio.Desktop** — WPF interface, dark theme, assignment view, macro editor, and update flow.
- **HarrowStudio.Setup** — project-local Windows installer with per-user setup and uninstall registration.

The UI uses C# and WPF on .NET 10. No third-party NuGet packages are required. The official Redragon product banner is stored at `assets/harrow-pro-reference.jpg`; the transparent G808 front view is stored at `assets/harrow-pro-660x520-1.png` and used by the interactive assignment screen. The project icon is generated by `scripts/generate-icon.ps1`. Main views switch to a compact navigation rail and stacked panels on narrower windows, with larger text throughout.

## Releases and updates

Download the installer from [GitHub Releases](https://github.com/JUANJOPROGRAM/HarrowPROsftw/releases). Harrow Studio checks the latest stable release at startup. When a newer release is available, the title bar offers an update button; confirming downloads `HarrowStudioSetup.exe` and installs it over the current installation. The update preserves the current install path and local profiles.

To publish a version, update the `Version` in both project files, build the installer, commit the changes, and push a matching version tag such as `v0.1.2`. The `Publish Windows release` workflow builds the self-contained installer and attaches it to the GitHub release. The app version and tag must match for update detection.

## Run from VS Code

Open `HarrowStudio.sln`, then run:

```powershell
dotnet restore HarrowStudio.sln -m:1
dotnet run --project src/HarrowStudio.Desktop/HarrowStudio.Desktop.csproj
```

The `-m:1` setting avoids a restore graph issue in this restricted Windows environment. The local `.devhome`, `.packages`, and `.nuget-http-cache` folders keep development state inside the project.

## Build the installer

Run this from PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/build-installer.ps1
```

The script publishes a self-contained Windows x64 build and creates `artifacts/HarrowStudioSetup.exe`. The installer asks whether to create a desktop shortcut, creates a Start Menu shortcut, and registers an uninstall entry for the current Windows user. The .NET runtime and restore packages are kept in the installer payload and the project-local `.packages` cache.

Profiles are saved as JSON under `%LOCALAPPDATA%\HarrowStudio\profiles`.

## Current status

The app reads compatible XInput/DInput controllers and saves button assignments and macro sequences in a profile. Applying those mappings and macros to games still requires a Windows virtual gamepad output driver, which is not bundled or installed by this prototype.
